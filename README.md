1. Снаружи по SSH никто не подключится. Привязка сервиса главнее, потому-что работает раньше и жёстче. Firewall лишь решает дойдёт ли пакет, а привязка определяет есть ли вообще получатель. Пакеты приходят на 203.0.113.10:22, но никто не слушает этот адрес. Ядро ответит соедениение отвергнуто, хотя itables пакет пропустил. Для доступа к сервису важны оба условия. Пропуск firewall и чтобы сервис словал нужный адрес.
2. Нужно 3 вещи: Маршрут поумолчанию внутри namespace. Включенная пересылка на хосте. MASQUERADE в POSTROUTING.
   Адрес 10.200.0.2 - приватный, и в интернете не маршрутизируется. Если пакет уйдёт с таким источником, он будет отброшен провайдером, либо сервер ответит на адрес, который до нас не доберётся. Маскарад в последнийй момент подменяет источник на 203.0.113.10 и запоминает соответствие в таблице соеденений. Ответ приходит на вешний адрес, а ядро возвращает по этой записи на 10.200.0.2.
3. В PREROUTING докер делает DNAT, адрес назначения меняется с 203.0.113.10:8080 на 172.17.0.2:8080. После этого пакет уже не для этой машины, а транзитный, поэтому идёт в forward, а не input. Input его не видит, так-что отсутствие правила на 8080 ничего не меняет. Докер пишет свои правила в форвард, поэтому запрет не срабатывает.
4. В варианте а не будет TLS-терминации, нет роутинга по домену или пути (Пользователю нужно будет помнить все порты), больше открытых портов в файрволле (Шире площадь для атаки)
